# Worker lifecycle review — 2026-10-09

Reviewed baseline: `b37d053`, after the durable lifecycle increment. Scope:
scheduler admission and cancellation, episode lifetime, persisted recovery,
runtime cleanup, and the evidence produced by the VM rehearsal. This is a focused
code and failure-path review, not a comprehensive security audit.

## Findings and fixes

### R1 — Cleanup cancelled unrelated workers (high impact)

The scheduler treated every lifecycle admission block like an instruction to stop
all running work. When one worker completed and entered `stopping`, the next tick
aborted its peers. A small team could repeatedly interrupt its longer tasks as
shorter tasks finished. The single-worker pause/crash trials did not expose this.

A new regression test reproduced cancellation of a healthy peer while a separate
worker was stopping. The scheduler now distinguishes an execution stop (pause,
unavailable quota, working-hours boundary, runtime error) from a resource admission
block. Cleanup still prevents new work; already admitted healthy peers retain
their controllers and authenticated tool access. An operator pause still stops
them even when a lifecycle block is also present.

### R2 — Successful completion left the episode signal active (medium impact)

The lifecycle cancelled the episode signal on pause, shutdown or deadline, but
not on ordinary success or a work error. A host operation started by the worker
callback and listening for cancellation could outlive the logical episode and
overlap removal. VM removal alone did not notify that operation to stop.

A new regression test reproduced an active background operation at the start of
cleanup. Every exit from provisioning/work now ends the internal episode signal
and clears its deadline before resource removal. This revokes tokens immediately
and tells in-flight operations to stop. Cleanup retains its independent command
budgets. Successful work still yields a completed run, rather than being recorded
as an operator interruption.

## Verification

Both regressions failed against the reviewed baseline and passed after the fixes.
The scheduler test uses two durable worker identities, verifies that the peer's
token remains valid, confirms new work stays pending, and then verifies pause.
The episode test verifies cancellation occurs before the backend removes the VM.

The [new VM evidence](worker-lifecycle-review-results.json) extends the rehearsal
to three cases: ordinary completion, pause with an uncooperative callback, and a
supervisor killed with `SIGKILL`. Each first performs an authenticated domain-tool
call from an actual pinned VM. Cleanup/recovery must remove its resources and
private fixture, preserve unrelated VMs, and retain the correct completed versus
interrupted run status. No model is invoked.

Final validation passed: all 141 regression tests, type checking/compilation,
all three real-VM trials, and the documentation catalog/link checks. The saved VM
report matches the reviewed implementation's source fingerprint.

## Decision and remaining boundaries

Proceed to bounded workspace/artifact transfer using this corrected lifecycle.
The existing live-worker gate remains closed. Clipboard-write containment,
provider authentication/billing/quota compatibility and real model/session
behavior still need their own evidence. Unacknowledged create dispatch remains an
explicit operator-reconciliation case; this review adds no unsafe automatic reset.

The original [implementation report](WORKER-LIFECYCLE.md) and its two-case VM
report remain historical evidence. The [lifecycle design](designs/06-worker-lifecycle.md)
now explicitly distinguishes admission blocks from cancellation of healthy peers.
