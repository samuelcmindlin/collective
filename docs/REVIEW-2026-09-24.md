# Worker boundary and rehearsal review

Status: review fixes verified, 2026-09-24. Reviewed the worker probe, its host-side
acceptance logic, cleanup, native live gate and isolation claims before expanding
the adapter. The production native gate remains closed; no model was invoked.

## Findings and fixes

| Finding | Evidence and consequence | Correction |
| --- | --- | --- |
| Missing observations could silently disappear | The host iterated whatever keys the VM returned; it did not require the complete inventory | A versioned, framed result and strict schema are required. Missing/extra observations, duplicate records, unexpected output and invalid runtime identities fail |
| Heartbeat read could be empty during a write | The original [report](worker-rehearsal-results.json) contains an empty `beforeStop.heartbeatAfter`; string inequality accepted it as activity | Atomic temporary-file replacement in the fixture; the host requires nonempty numeric timestamps and complete lifecycle records |
| Failed commands could be mistaken for denial | Any nonzero direct-request exit was accepted, including timeouts or broken tooling | Effective daemon policy is checked, host reachability is a positive control, proxy 403s and the observed direct HTTP/TLS failure modes are checked explicitly |
| Cleanup could wait for an incomplete HTTP connection | The host counted requests, not connections, then waited for server shutdown | Track connections, count attempted host access and destroy owned connections before closing the server |
| A crash could lose the VM identities needed for cleanup | The only report write happened after the experiment | Persist intended identities before creation and checkpoint progress. A pass is written only after verified cleanup. Graceful cancellation stops the client and runs cleanup; report-write failure cannot skip VM removal |
| Rehearsal code was outside TypeScript checking | The `.mjs` host script was excluded from the build's input patterns | Converted the host rehearsal to TypeScript, with separately testable protocol validation and bounded command execution |

An immutable report of the old observation is retained. The new validator rejects
the empty heartbeat; the fix does not reinterpret it as valid evidence. The
earlier host-file and network observations remain useful, but the old headline
of 60 passing assertions was not sufficient to validate all lifecycle readings.

## Verification

- **123 application/regression tests passed**, including six new tests covering
  malformed or contradictory evidence, missing lifecycle files, output floods,
  cancellation before spawn, and a wrapper descendant holding output pipes open.
- The revised [real VM report](worker-review-results.json) passed **67 checks**.
  It contains complete heartbeat readings, host reachability controls, actual
  per-VM policy decisions and verified cleanup for both VMs.
- An additional synthetic marker in Claude's project-state volume remained
  private between VMs and survived stop/restart. This is filesystem persistence,
  not a real Claude conversation-resume test or verification of every volume.
- Live and demo databases were not used by either rehearsal. Schema and the
  native launch gate did not change.

The check count is an inventory, not a security score. This is controlled-fixture
evidence for one runtime/configuration. The direct-network assertions deliberately
fail if runtime behavior changes; diagnose that change rather than widening the
accepted error set until the check turns green.

## Proceeding after the review

Continue with the smallest host-integration experiment: fixed MCP membership.
Register two temporary, maintainer-written arithmetic-only MCP fixtures and give
one test VM access to just one of them. Verify both ordinary tool listing and
direct requests through the gateway. A hidden tool in Claude's configuration is
not sufficient: the host must reject a worker that explicitly requests the other
server. Remove the test VM and registrations afterward. This does not authorize
model use, platform mutations or any external public action.

The remaining [worker design gates](WORKER-REHEARSAL.md#next-implementation-one-bounded-worker-episode)
remain open: clipboard writes, authenticated provider scope, fixed tool authority,
durable run reconciliation, model-session resume and quota. Review of the
installed settings found no clipboard-write disable switch; image paste controls
reading images only. Do not remove an in-VM helper and call that host enforcement.

The CLI now exposes the cached template's image digest via `sbx inspect`:
`sha256:549730947ed8a43182547bb5628245fe6d6c089564dd73d2194e899f791d970f`.
This identifies the observed image; acceptance of that identity as an offline
creation reference still needs a compatibility check before claiming pinned launches.
