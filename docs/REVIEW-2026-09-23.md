# Knowledge and evidence review — 2026-09-23

Status: completed local review and corrective increment, following baseline
commit `84a0e7d`. This is a focused review of the knowledge handoff and artifact
evidence paths, not a full security audit or live multi-agent quality evaluation.

## Decision

Keep the modular application and SQLite foundation. Fix the reproduced defects
before adding evaluation records; a wholesale refactor is not justified by this
review. The existing 79 checks passed, but four new regression probes failed.
Green tests established the behavior they covered, not completeness of coverage.

## Findings and fixes

| Finding | Failure reproduced | Implemented correction |
| --- | --- | --- |
| K1: revision recency | Revising an old document after 30 newer documents left it outside recent context | Catalog/context order follows the latest appended revision, using the document's revision index, rather than document creation order |
| K2: catalog continuation | An agent received `nextOffset` but its search tool rejected `offset` | Agent and operator catalog browsing accept bounded offsets; keyword search explicitly rejects unsupported offsets rather than silently repeating page one |
| K3: conflict metadata growth | A legacy document with 2,000 competing heads made context/history metadata unbounded | Context gives a head count; history pages heads separately and labels each revision with `isHead`; every head remains accessible |
| A1: unchecked artifact bytes | Same-length replacement bytes were returned with the original hash | One bounded reader checks file type, size and SHA-256 before agent reads, previews/downloads, submissions and acceptance |

The artifact reader rejects missing snapshots, escaped paths, a symlinked storage
directory, leaf symlinks, nonregular files and oversized metadata. It reads through
one descriptor with a bounded allocation. Failed reads create no inspection event;
failed submission/acceptance changes no task, counter, job, audit event or command
receipt. Rejection remains possible when evidence is corrupt. Successful text
reads expose truncation and audit the hash, size and number of characters returned.
Binary metadata is returned only after verifying the underlying snapshot.

The UI now says **reviewed work** and **tasks accepted by review**. A file hash and
another agent's agreement do not establish correctness or mission attainment.

## Interface and recovery limits

- `knowledge_search` with an empty query accepts `limit` (1–20) and `offset`
  (0–100,000). Follow `nextOffset` until null. Catalog order is the current view;
  concurrent writes can shift offset pages. Restart browsing after changes when
  complete enumeration matters. Keyword search remains a top-20 lexical query;
  narrow or change terms for additional results.
- `knowledge_history` uses `offset`/`nextOffset` for revisions and
  `headOffset`/`nextHeadOffset` for heads. `document.heads` contains at most 20 IDs;
  `headCount` is the full count. `isHead` is computed against the full set, even
  when that head is absent from the head page.
- The existing merge command still accepts at most 100 heads. Larger legacy
  conflicts remain readable and require a maintainer recovery request. This
  increment does not silently discard heads or invent a current version.
- Artifact integrity is checked against trusted stored metadata at the time of
  reading, submission or acceptance. An already committed command retry returns
  its original receipt; it is not a fresh integrity assessment. Historical
  acceptance is not silently undone if a file is later damaged.
- Restore the original bytes from a trusted backup or publish a new artifact
  and resubmit if an integrity check fails. Do not rewrite the old hash to bless
  changed evidence. There is no automatic corruption repair in this increment.

## Remaining architecture boundaries

The new reader detects corrupted evidence; it does not isolate a worker that can
write supervisor files or its database. Publication still has a path-check/read
race, and snapshots are filesystem effects outside SQLite rollback. Worker
containment, publication race closure and artifact backup/restore rehearsal remain
required before a live coding pilot. Protected evaluation code needs that same
separation of authority.

At present, catalog ordering sorts eligible documents, keyword caches rebuild a
principal's full visible corpus, and artifact checks synchronously read up to
5 MB per artifact (at most 20 per submission). These bounded personal-use paths
are not evidence for multi-host operation or the larger performance targets.
Other domains still have unbounded history reads/context. Measure representative
growth before replacing storage or adding distributed services.
